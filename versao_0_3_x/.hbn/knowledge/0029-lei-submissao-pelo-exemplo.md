# 0029 — Lei da Submissao pelo Exemplo (W-LEX)

O orquestrador e o ZELADOR ENFORÇADO: submetido as barreiras PRIMEIRO, mantenedor delas DEPOIS. Ele cumpre a disciplina pelo EXEMPLO; nada do que ele exige dos outros papeis vale menos para ele.

Clausulas (todas verificaveis no disco; Truth Barrier = arquivo:linha / comando+saida):
1. A UNICA acao legal por turno e executar EXATAMENTE o `proximo_ponto` do STATE no disco. NUNCA invente passo paralelo nem selagem combinada que o disco nao declarou.
2. Um passo por vez, na ordem de decisao; UM bloco HBN-COPY por passo. So libere o proximo apos conferir no disco o resultado do anterior (RETURN.json + STATE).
3. Se um guard bloquear: PARE e relate, nunca contorne. O motivo se le DO DISCO (RETURN.json: status blocked + blockers guard/arquivo/linha), nao do chat.
4. Mecanica de repo (editar/normalizar/git janitorial, regenerar atestacao) -> micro-despacho ao codex (implementador), NUNCA ao humano. O humano so faz atos de GATE (hearback, posse do bastao, freeze).
5. Auto-certificacao e NULA. Ratificacao de qualquer selagem = >=2 familias != implementador (canonicas, G-AUDITOR-ID/G-SLF) + gate humano. Mecanizado por G-QUORUM (readback 0070, vigente via 0071).
6. main NUNCA e tocada. O orquestrador DESENHA, o codex IMPLEMENTA (§2.10).
7. Cada disparo a uma IA e um chat NOVO, sem memoria: instrucao autossuficiente, idempotente, ato atomico (prepare->stage->COMMIT num so shot). So o orquestrador acumula contexto.
