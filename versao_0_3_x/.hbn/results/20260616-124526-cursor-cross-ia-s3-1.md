### B1. Onde a IA deve criar efêmeros?

Para provar guards: `git add` + `git reset` sem deixar arquivo no worktree.

### B2. Se inevitável no repo

**Recomendação:** única pasta oficial `/scratch/` na raiz do repositório:

1. Entrada em `.gitignore`: linha ancorada `/scratch/` (não `scratch/` solto).
2. `scratch/README.md` versionado (não ignorado) declarando: efêmero, sem segredos/PII, limpeza ao fim da sessão, proibido symlink.
3. Conteúdo sob `/scratch/**` nunca versionado.

### B3. Gitignore + anti-stage — suficiente?

**Não.** Gitignore sozinho não fecha os três vetores de exposição:

| vetor | risco | mitigação proposta |
|---|---|---|
| **(a) Backup** (Time Machine, sync cloud, snapshot CI) | dados em `/scratch/` persistem no disco mesmo ignorados pelo git | política documental: sem segredos em scratch; exclusão de `/scratch/` em configs de backup/sync; CI não arquiva worktree; limpeza best-effort ao fim da sessão |
| **(b) Symlink para fora** | `scratch/link → ~/.ssh/id_rsa` expõe fora da árvore ignorada | **G-SCRATCH-SYMLINK**: no pre-commit, para cada path staged sob `scratch/`, `readlink`/`realpath -P`; bloquear se symlink ou se destino resolve fora de `$REPO_ROOT/scratch/` |
| **(c) Remoção da linha do gitignore** | `git add scratch/secret.txt` após editar `.gitignore` | **G-SCRATCH-LOCK** (independente de gitignore): falha se qualquer path staged começa com `scratch/` (`git diff --cached --name-only`). **G-SCRATCH-IGNORE**: se `.gitignore` estiver no diff, exigir que o blob staged ainda contenha linha exata `/scratch/` |

### Guard sugerido (esboço mínimo)

Novo `guards/assert-scratch-isolated.sh` (G-SCRATCH-LOCK), inserido cedo no runner após `assert-scope-lock`:

```bash
# Falha se qualquer path staged está sob scratch/
while IFS= read -r f; do
  case "$f" in scratch/*|scratch) guard_fail "scratch staged: $f"; exit 1 ;; esac
done < <(git diff --cached --name-only --diff-filter=ACMR)
# + ramo symlink: find scratch -type l → realpath fora de REPO/scratch → block
# + ramo .gitignore: grep -qxF '/scratch/' no staged .gitignore quando .gitignore staged
```

Defesa em profundidade: gitignore (conveniência) + anti-stage (commit) + anti-symlink (exfiltração lateral) + integridade do gitignore (tampering) + política de backup (operacional).
