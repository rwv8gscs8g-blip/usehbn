## A3. PROMOCAO APPEND-ONLY (confirmado em spec + guard)

**core/arvores-spec.md (l.42-46):**
> Promocao de arvore e sempre evento append-only no REGISTRY, com `tipo=arvore-promocao`. A linha original de nascimento nunca e editada em lugar para trocar a arvore.

**Design-fonte (seção 1.4):**
> Promover (fronteira→intermediaria→estavel) é acrescentar uma nova linha-evento no REGISTRY (`tipo: arvore-promocao`) que referencia o readback/cross-audit que autorizou — NUNCA editar em-lugar a linha original.

**Guard assert-arvore-label.sh (l.130-140):**
```bash
if [[ "$arvore" == "intermediaria" || "$arvore" == "estavel" ]]; then
    if [[ "$tipo" != "arvore-promocao" ]]; then
        guard_fail "... sem evento tipo=arvore-promocao. Artefato nasce fronteira; intermediaria/estavel so por promocao append-only."
    fi
    if ! readback_ref_exists "$line"; then ... fi
fi
```

- Requer TIPO da LINHA NOVA == arvore-promocao + referência a readback versionado.
- Não há edição da linha de nascimento (o guard só olha linhas ADDED `git diff ... | grep '^+|'`).
- REGISTRY atual não contém nenhuma linha com arvore-promocao (todos os 12 artefatos R2 nasceram fronteira) — correto, sem promoção ainda.

Nenhum código permite "UPDATE em lugar" da coluna arvore na linha original.

## A4. G-NUM / created_at COLUMN-AWARE (confirmado arquivo:linha)

**Arquivo:** `guards/assert-parallel-id.sh`

- Linha ~19 (comentário): "O parser é column-aware: aceita o bloco legado de 6 colunas e o bloco novo de 7 colunas com arvore (R2/readback 0049)."
- Linha ~180-181 (função):
  ```bash
  registry_last_cell() {
      awk -F'|' '{ idx=NF-1; gsub(/^[ \t]+|[ \t]+$/,"",$idx); print $idx }' <<< "$1"

  ```
- Uso na regra 2 (l.188): `created="$(registry_last_cell "$line")"`
- Erro explícito (l.190): "... em bloco legado de 6 colunas ou novo de 7 colunas com arvore."

  - data divergente id vs created_at → block

G-REG também usa column-aware para path (coluna 2) e arvore (apenas >=7).

A4: leitura created_at column-aware (6-col e 7-col) sem quebrar legado. Confirmado em assert-parallel-id.sh:180 (registry_last_cell + NF-1 + comentários + mensagens). PASS.

- Selagem 4 batch1 (untracked, sem SOU canônico ainda)
