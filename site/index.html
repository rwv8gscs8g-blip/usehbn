Protocol

What HBN is

HBN is not a product, framework, or hidden reasoning engine. It is a protocol layer for AI-assisted software work: explicit activation, structured intent, visible validation, readback discipline, and documented results under human authority.

Why it exists

Human control must remain legible

AI-assisted work moves faster than review, validation, and traceability in most teams. HBN exists to keep constraints, risks, assumptions, and approvals visible enough to inspect.

What it is not

No hidden orchestration claims

HBN does not claim AGI, autonomous governance, or invisible background processing. The current release is a minimal executable protocol scaffold with explicit boundaries.

Public identity

One canonical site, two semantic anchors

usehbn.org is the canonical public site. usehbn.com is the redirect alias. Both are documented as protocol identity anchors across human and machine-facing contexts.

Execution model

How HBN works

  1. Activate with usehbn or use hbn.
  2. Normalize semantic anchors such as usehbn.org and usehbn.com.
  3. Structure objective, constraints, risks, and validation requirements.
  4. Run truth barrier and guardian checks.
  5. Require readback and hearback where the execution track demands it.
  6. Persist logs, state, and ERP records under human authority.

Install

Local bootstrap

Current primary path:

./get-hbn
hbn run "use hbn analyze this system"

The public site is canonical. The operational runtime is still local-first and explicit.

Analytics

Visit tracking

This site can be tracked through Cloudflare Web Analytics with a manual beacon snippet, because the canonical site is served by GitHub Pages while DNS remains managed in Cloudflare.

The repository documents the domain strategy and is ready for analytics configuration, but the site token must be generated in Cloudflare before the beacon can be activated.
